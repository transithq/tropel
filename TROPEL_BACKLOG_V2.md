## §0 · ✅ THE UNITS PROBLEM IS FIXED

- [x] **µs → ms migration is complete and verified end-to-end.** Every emitter produces ms (`runner.rs:518`, `vu_loop.rs:205`, `driver.rs:867,891`, `tropel-x-grpc:537`, `wasm/driver.rs:770`); the ms→µs `*1000` is deleted from the k6 threshold translator and the `/1000` heuristic is gone from the reporters. **CLI/YAML thresholds and k6-script thresholds now provably mean the same thing.** This was the largest cross-cutting defect in the previous pass.

Adopt k6's `Time`/`Data`/`Default` model.
- [ ] **P3 · Stale µs comments on live code** — `tropel-runtime/runner.rs:566` ("all in μs", 27 lines above a `*1000.0`), `tropel-report/output.rs:195`, and ~8 collector tests encoding 25 ms as `25_000.0` (they exercise a unit production no longer uses).

- [ ] **P1 · Bodies dropped for DELETE/OPTIONS/TRACE** and `Method::Custom`. `protocolProfileBehavior` (and `disableBodyPruning`) still absent repo-wide.

- [ ] **P2 · Duplicate header/query/form keys collapse** into `HashMap`s; the duplicate-query fold doesn't URL-encode (asymmetric with the non-duplicate path, which reqwest encodes correctly).

- [ ] **P2 · Ramp-down is a cliff, not a ramp.** `set_ramp_down_target` **stores** `remaining`, so each step overwrites the previous with 1 and unclaimed slots are discarded. - [ ] **P2 · No executor replaces a VU that dies mid-run.** `current_vus` is pure bookkeeping; only externally-controlled reconciles. A VU panicking at iteration 500 of a 30-min run leaves the test at 99 VUs, then 98… `vu_init_failures` counts only startup, so exit 0 and the summary reports the requested count.
- [ ] **P2 · A panicked scenario task orphans its VUs.** `make_worker` still `.expect()`s on `Runtime::build`; the panic aborts the scenario task mid-ramp, and `request_stop()` lives at the tail of `run_*` which never returns. - [ ] **P2 · Control API: 5 of 6 unfixed.** Unbounded `body.resize(content_length)` (`Content-Length: 68719476736` → 64 GiB alloc, no ceiling), no read timeout, no connection cap, hot-spin on accept error (100 % CPU under EMFILE), and `PATCH {"stopped":true}` → 400 so the run doesn't stop (`stopped` is *emitted* but never *read*). Plus the `control_spawned` lost update (absolute `store` overwrites concurrent guard decrements → pool permanently undershoots).
- [ ] **P2 · Per-VU `vus`/`vus_max` storm got broader** — a 2 s time-based trigger was added *on top of* the every-100-iterations one, so 1000 VUs now emit ~1000 `record_batch` calls per 2 s floor. It fixes the real bug (short runs reporting `vus_max: 0`) but belongs in a single scheduler sampler task. Also corrupts the gauge: min/max/avg over ~1000 duplicate readings.
- [ ] **P2 · Arrival-token acquisition: single-shot CAS + lost wakeup.** `try_acquire_arrival_token` isn't a retry loop; the caller then parks on `Notify::notified()` created *after* the failed check — the classic misuse. No notify is sent when the bucket is full (`actual_add == 0`), i.e. exactly under sustained overload. Self-heals, but it undermines the pressure-based growth heuristic (`idle != 0` → refuses to grow).
- [ ] **P2 · No SIGINT/Ctrl-C handling** — zero matches repo-wide. No drain, no summary, no reporter flush; streaming outputs lose their unflushed batch.
- [ ] **P3 · Think-time sleep isn't interruptible** — with `iteration_pacing: "30s"` a stopped VU holds its lease for 30 s, turning a clean shutdown into ~90 s. P3 · `find_idle_slot` is an O(n) scan under a global mutex per spawn. P3 · arrival bucket capacity is still `max_vus`; `dropped_iterations` is still one end-of-run sample.

## §8 · New crates — `tropel-sandbox` / `tropel-web`

**What they are:** `tropel-sandbox` is **JS language bindings** (hand-written rquickjs glue registering ~55 globals for the `pm.*`/`trp.*` API) — **zero `unsafe`, no raw pointers, no guest lengths**; it is wired in and reachable from all four binaries. `tropel-web` is the real ABI crate: `tropel-runtime` compiled to `wasm32-wasip1` as a `cdylib` with `tropel_alloc`/`free`/`run`/`version`, postcard over linear memory, HTTP delegated back to a JS host. **`tropel-web` has zero Rust dependents** — it isn't even in `[workspace.dependencies]`. Its consumers are the CI `wasm` job (a real gate: builds, 8 MB size cap, runs the differential with `TROPEL_REQUIRE_WASM=1`) and the npm package `@tropel/exec-wasm`.

- [ ] **P0 · The two wire bugs** — see §1.
- [ ] **P1 · Neither gate can catch either P0.** The Rust `native_vs_wasm` harness encodes responses with the **real Rust `Serialize`** — a second, correct host — so it passes while the shipping TS host is broken; and both legs run the same source, so it can never prove correctness, only build-equivalence. The npm smoke test asserts **only counts** (`checks.length >= 2`, `scriptFailures === 0`) — never that a check *passed* or that `http_req_failed` is 0. Two one-line assertions would have caught both P0s.
- [ ] **P1 · `tropel-web/src/bootstrap.rs` is a divergent fork** of the engine's VU bootstrap. (a) **Uninterruptible sleep** — one un-sliced `thread::sleep`, so `sleep(300)` blocks 300 s (the engine slices at 10 ms). (b) **No force-stop flag at all** — `JsContext::new` allocates a fresh `AtomicBool` nobody holds, so the interrupt handler checks a flag that can never be set; `exec.scenario.executor()`/`vusActive`/`iterationsCompleted` are all dead. (c) No `SandboxConfig` preamble. (d) **Silent failure with zero logging** — returns `None` on every error path, and the run then proceeds **with no scripts at all** and reports success.
- [ ] **P1 · Unbounded allocation + no panic barrier on the C ABI.** `Vec::with_capacity(req.iterations as usize)` on an unvalidated `u64`; `tropel_alloc` does `vec![0u8; len]` with no ceiling (aborts rather than returning null, which the ABI can't express). **No `catch_unwind` anywhere** — `tropel_run` is `extern "C"` and drives 57 `.lock().unwrap()` sites; the documented *"returns 0 on fatal internal failure"* contract has no reachable implementation.
- [ ] **P1 · `bru.js` is in the web bundle but in *no* CLI bundle.** `ShimBundle::default()` lists 6 files; the constant the engine actually executes (`JS_SHIM_BUNDLE`) lists 5 — no `bru.js`. Same `SHIM_BUNDLE_VERSION`, which can't express the difference. **And the obvious fix is a trap:** `bru.js:212-214` installs `res`/`req` as **non-writable non-configurable globals** — ✅VERIFIED `var res = http.get(...)` is silently dropped in sloppy mode and TypeErrors in strict. - [ ] **P2 · `bru.assert` is broken twice** — passes a number into a `bool` bridge param (✅VERIFIED `TypeError: expected bool`, so **every** call throws), and `eval(expr)` inside a bare try/catch turns a typo into a silently *failed* assertion.
- [ ] **P2 · `tropel-web` silently ignores `Request.auth`** — no `tropel-auth` dependency, and the TS decoder stops after `body`. A collection with Bearer/SigV4 runs **unauthenticated** in the browser. Same decoder drops `timeout`, `follow_redirects`, `responseType`. The comment claiming *"nothing follows body on the wire"* is false.
- [ ] **P2 · `trp.rs` has a second, weaker `Method` parser** — no tchar validation, empty → `GET`, and it **uppercases** `Method::Custom` (so `myMethod` → `MYMETHOD`) while the SDK preserves case. `Method::Custom("GET /X HTTP/1.1\r\n…")` is constructible from a script. `pm.sendRequest` **in the same file** uses the correct `Method::parse`.
- [ ] **P2 · Counter metrics return the last value, not the total** — `custom_metrics.insert(name, value)` overwrites, keyed on name only (tags ignored, contradicting its own comment). `counter.add(1)` ×10 → `get()` returns 1.
